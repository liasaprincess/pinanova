# Pinanova website

Moody botanical landing page and separate collection preview, About, Contact, Terms & Conditions, and Store Policies pages.

## Run the source folder

This is editable website source, not a folder of HTML files that can be opened by double-clicking. Install Node.js 22 or later and Bun, then run:

```sh
bun install
bun run dev
```

Open the local URL shown in the terminal. To create a deployment build, use `bun run build`.

## Contact requests

The live Lovable project stores name-and-email requests privately in Lovable Cloud → Database → `contact_submissions`. The form has been tested through the browser and its saved record verified. Owner notification emails are not enabled.

The downloaded source does not include secrets. A standalone deployment needs Cloud-compatible environment bindings: `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` on the server, and `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` for the browser. Lovable supplies these to the connected project; do not place private keys in browser variables. Without a configured connection, the pages work locally but contact submissions report an error rather than pretending to save.

## Content status

- Collection photos are generated editorial previews, not actual product listings. No checkout is included.
- About and supporting landing-page copy were drafted and need owner review.
- Terms and policies are reserved pages without invented legal text. The supplied PDF was a brand guide, not a policy document.
- Headings use italic Cormorant Garamond at regular weight; the PINANOVA wordmark stays upright and uppercase. Body text uses DM Sans as a fallback until a licensed TT Commons Pro font is supplied.
- Generated imagery is bundled in the source folder; original uploaded reference screenshots are not embedded.

## Where to edit

Start with these files for common changes:

| To change | Edit |
| --- | --- |
| Home page content and sections | [`src/routes/index.tsx`](./src/routes/index.tsx) |
| Collection, About, Contact, Terms, or Policies page | The matching file in [`src/routes`](./src/routes) |
| Shared header, navigation, and footer | [`src/components/site/site-shell.tsx`](./src/components/site/site-shell.tsx) |
| Collection preview cards | [`src/components/site/collections.tsx`](./src/components/site/collections.tsx) |
| Site-wide colors, typography, and layout styles | [`src/styles.css`](./src/styles.css) |
| Homepage and collection imagery | [`src/assets`](./src/assets) |
| Contact form validation and submission | [`src/lib/contact-schema.ts`](./src/lib/contact-schema.ts) and [`src/lib/contact.functions.ts`](./src/lib/contact.functions.ts) |

## Folder map

This project uses React 19, TanStack Start, TypeScript, and Tailwind CSS v4.

```text
.
├── public/                 Static files served as-is (favicon, robots.txt)
├── src/
│   ├── assets/             Images imported by the website
│   ├── components/
│   │   ├── site/           Shared Pinanova sections and site shell
│   │   └── ui/             Reusable interface building blocks
│   ├── hooks/              Shared React hooks
│   ├── integrations/       External service integrations (Supabase)
│   ├── lib/                Shared helpers, metadata, and contact logic
│   ├── routes/             One file per page/route
│   ├── test/               Test setup and route tests
│   ├── router.tsx          Router setup
│   ├── server.ts           Server entry point
│   ├── start.ts            TanStack Start setup
│   └── styles.css          Global website styles
├── drizzle/
│   ├── migrations/         Database migration files
│   └── schema.ts           Database schema
├── package.json            Scripts and dependencies
└── vite.config.ts          Vite configuration
```

The route files are the page content: `index.tsx` is `/`, `collection.tsx` is `/collection`, `about.tsx` is `/about`, and `contact.tsx`, `terms.tsx`, and `policies.tsx` provide the other pages. `__root.tsx` sets up the shared root layout. `routeTree.gen.ts` is generated by the router; do not edit it manually.

To run the site locally, use the commands in [Run the source folder](#run-the-source-folder) above. The generated collection imagery is for editorial previews only, not purchasable inventory.
